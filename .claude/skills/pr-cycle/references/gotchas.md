# pr-cycle — 실측 근거

## `--auto`를 빼면 안 된다

`gh pr merge --squash`(즉시 머지)는 **체크가 보고되기 전에 머지가 나간 적이 있다.**
main은 `strict`(브랜치가 최신이어야 함) + 필수 체크 `ci`가 걸려 있는데, 체크가 아직
등록되지 않은 찰나에 요청이 들어가면 통과해 버린다. `--auto`는 green이 될 때까지
GitHub이 들고 있다가 머지하므로 그 창이 없다.

보호 규칙이 요구하는 체크는 **`ci` 하나뿐**이다 — matrix(Node 20·22) 위에 이름이 고정된
집계 job을 두고 그것만 요구한다. matrix에 Node를 넣고 빼도 보호 규칙은 건드리지 않는다.

## 로컬 원격 ref는 낡는다 — 스테일 브랜치로 오독하지 말 것

저장소가 `delete_branch_on_merge: true`라 머지된 원격 브랜치는 GitHub이 지운다.
그런데 `git fetch`(--prune 없이)는 사라진 ref를 로컬에서 안 지우므로 `git branch -a`가
계속 보여준다. 2026-08-07 세션 초에 이걸 보고 "스테일 브랜치 3개"라고 보고했는데
원격에는 이미 없었다. **`git fetch --prune` 후에 판단한다.**

## 카운트는 손으로 세지 않는다

`npm run check`가 보는 카운트(looseObject·z.object·TR fixture 파일 수·tool 수)는
`npm run check:write`가 실제 값으로 고쳐 준다. 손으로 세면 틀리고, 틀린 숫자를 커밋하면
다음 세션이 그 숫자를 믿는다. **버전은 정답을 모르므로 `--write`가 건드리지 않는다** —
그건 손으로 5곳을 맞춘다.

## tool을 붙였으면 머지 전에 눈으로 본다

`python3 scripts/sweep.py --only <tool> --full`. 기본 스윕은 응답의 **첫 줄만** 찍어서
표가 깨졌는지·각주가 빠졌는지·가드 문구가 도는지를 못 잡는다. 라이브 크리덴셜이 필요해
CI에 없으므로 이 확인은 사람이 해야 한다.

## 요청 body의 버그는 포맷터 테스트로 안 잡힌다

v0.45.0~0.46.0이 거래원 TR을 KRX 기준으로 부르고 있었는데(접미사 누락) 테스트는 전부
초록이었다 — 포맷터는 받은 값을 그대로 렌더할 뿐이라 **원리상** 못 잡는다.
`api.ts`의 요청 조립을 바꿨으면 body를 직접 단언하는 테스트를 붙인다
(`tests/broker-exchange-basis.test.ts`가 그 꼴이다).
